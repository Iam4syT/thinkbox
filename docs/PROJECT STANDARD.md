# Project standard

Preserve the three established categories and each existing project's source layout. Choose the exact Category/Project destination before building. New workplace problems belong under Modern Workplace Solutions; AI-centred engineering belongs under AI Projects; general application design under Software Development. Do not duplicate a product for each job application.

Each project must describe the problem, intended user, personal contribution, implemented/simulated/planned scope, exact setup, baseline, actual evaluation and limitations. Maintain README.md, LAB.md, EVALUATION.md, DEMO SCRIPT.md, CONTRIBUTIONS.md and an append-only CHANGELOG.md. Add source, meaningful tests and permitted evidence; avoid empty folders and unsupported impact claims.

Two application-specific solutions remain distinct scenarios/projects, with private application requirements tracked outside this public repository. Never commit CV contacts, recruiter notes, credentials, tenant exports or private client data. Preserve upstream licences and third-party rights.

CI belongs at repository-root .github/workflows, with project working directories. Ordinary CI runs fixtures/builds only. Live operations need explicit scope and applicable authorisation; record proposals separately from performed actions. Scope git commits to the actual work and preserve unrelated user changes.

Before release, inspect the diff, run the relevant checks from a clean setup, verify links and inspect public evidence for private data. Record source revision, environment and actual result. Publish only claims supported by that evidence.
