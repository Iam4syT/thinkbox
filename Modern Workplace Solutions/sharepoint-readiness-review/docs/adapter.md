# Inventory and migration orientation — unimplemented and unrun

See LAB.md for official sources checked 30 September 2026. No tenant/client identifiers, credentials or vendor migration account are included.

A future collector must declare its site/library/list/content scope, complete all pages, preserve refresh/capture time and distinguish direct principals from effective access through group nesting, sharing links and inheritance. Only compute hashes from permitted actual bytes; do not copy a favourable source declaration into the destination to hide a failure. Compare intended renames/group mappings through an owner-approved mapping record. Content history, lists, workflows and compliance controls require separate acceptance checks.

ShareGate's documented pre-check sends migration calls without copying content and requires the relevant migration permissions. Read warnings, errors, mappings and unsupported objects; a clean pre-check is not successful migration evidence. BitTitan's checked SharePoint Online document-library scenario has licences, source/target constraints and supported/non-supported objects; it is not a general syncing service. Neither tool is run here.

Multi-Geo uses a primary/satellite model and separately licensed enterprise capability. A fixture geo string or geo_verified boolean does not verify tenant configuration, residency or compliance. Do not buy or configure the feature for this local demo; use the documentation/tabletop route unless a separately approved environment exists.

Required before live acceptance: source completeness, actual role/identity tests, owner-approved mapping, independently computed hashes, relevant metadata/list/history/compliance checks, failure recovery and cleanup. Preserve raw exports and screenshots privately; public evidence remains synthetic.
